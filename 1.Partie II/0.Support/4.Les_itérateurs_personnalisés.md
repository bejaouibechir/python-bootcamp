# 2️⃣ Comprendre le protocole d’itération

En Python, un objet est itérable s’il :

- Implémente `__iter__()`

- Et retourne un objet possédant `__next__()`

Cycle réel :

1. `iter(obj)` est appelé

2. Python récupère un iterator

3. Python appelle `next()` jusqu’à `StopIteration`

---

# 3️⃣ Implémentation naïve incorrecte (analyse d’erreur)

Avant la bonne version, observons une mauvaise conception fréquente.

Créer le fichier **iteration_incorrecte.py** :

```python
"""
Mauvaise implémentation volontaire.
Problème : l’index est partagé entre toutes les instances.
Cela provoque un comportement imprévisible.
"""

class Departement:

    __i = 0   # ❌ Attribut de classe (dangereux)

    def __init__(self, employes):
        self.employes = employes

    def __iter__(self):
        return self

    def __next__(self):
        if Departement.__i >= len(self.employes):
            raise StopIteration

        value = self.employes[Departement.__i]
        Departement.__i += 1
        return value


d1 = Departement(["A", "B"])
d2 = Departement(["X", "Y"])

for e in d1:
    print("d1:", e)

for e in d2:
    print("d2:", e)   # ⚠ comportement incorrect
```

🔎 Problème :

- L’index est partagé entre d1 et d2.

- Non thread-safe.

- Non conforme aux bonnes pratiques.

# 4️⃣ Implémentation professionnelle correcte

Principe :

- Séparer Iterable et Iterator

- Chaque itération crée un nouvel objet Iterator

---

Créer le fichier **iteration_propre.py** :

```python
"""
Implémentation professionnelle du protocole d’itération.

Nous séparons :
- Departement : iterable
- DepartementIterator : iterator

Cela évite les effets de bord et respecte le modèle Python.
"""

class DepartementIterator:

    def __init__(self, employes):
        self._employes = employes
        self._index = 0   # Index propre à chaque iterator

    def __next__(self):
        """
        Retourne l’élément suivant.
        Lève StopIteration lorsque la fin est atteinte.
        """
        if self._index >= len(self._employes):
            raise StopIteration

        value = self._employes[self._index]
        self._index += 1
        return value


class Departement:

    def __init__(self, employes):
        self.employes = employes

    def __iter__(self):
        """
        Chaque appel à iter() crée un nouvel iterator.
        """
        return DepartementIterator(self.employes)


# Démonstration observable

dep = Departement(["Alice", "Bob", "Charlie"])

for emp in dep:
    print(emp)

print("Deuxième boucle indépendante :")

for emp in dep:
    print(emp)
```

✔ Chaque boucle est indépendante  
✔ Aucun état partagé  
✔ Conforme au protocole Python

# 5️⃣ Comprendre StopIteration en profondeur

Créer le fichier **stop_iteration_demo.py** :

```python
"""
Démonstration du mécanisme réel de StopIteration.
"""

class Compteur:

    def __init__(self, max_value):
        self.current = 0
        self.max = max_value

    def __iter__(self):
        return self

    def __next__(self):
        if self.current >= self.max:
            raise StopIteration

        self.current += 1
        return self.current


c = Compteur(3)

it = iter(c)

print(next(it))
print(next(it))
print(next(it))

# La ligne suivante provoquerait StopIteration
# print(next(it))
```

Explication :

- StopIteration est un mécanisme interne

- La boucle for le capture automatiquement

- next() manuel ne le capture pas

# 6️⃣ Générateurs : version moderne et propre

Un générateur simplifie drastiquement l’écriture.

Créer le fichier **generateur_propre.py** :

```python
"""
Version générateur du département.

yield suspend l’exécution.
Aucune gestion manuelle d’index.
"""

class Departement:

    def __init__(self, employes):
        self.employes = employes

    def __iter__(self):
        """
        Cette méthode devient automatiquement un générateur.
        """
        for emp in self.employes:
            yield emp


dep = Departement(["Alice", "Bob", "Charlie"])

for emp in dep:
    print(emp)
```

✔ Plus court  
✔ Plus sûr  
✔ Lazy evaluation

# 1) Quelle différence exacte entre Iterable et Iterator ?

## Énoncé

Un objet qui possède `__iter__` est-il forcément un Iterator ?

## Solution

Créer le fichier **q1_iterable_vs_iterator.py** :

```python
"""
Explication

- Un Iterable possède __iter__()
- Un Iterator possède __iter__() ET __next__()
- Un Iterator retourne généralement lui-même dans __iter__()
"""

class IterableSeulement:
    def __iter__(self):
        return iter([1, 2, 3])


class IteratorComplet:
    def __init__(self):
        self.data = [1, 2, 3]
        self.index = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self.index >= len(self.data):
            raise StopIteration
        value = self.data[self.index]
        self.index += 1
        return value


i1 = IterableSeulement()
i2 = IteratorComplet()

print("IterableSeulement est itérable :", hasattr(i1, "__iter__"))
print("IterableSeulement est iterator :", hasattr(i1, "__next__"))

print("IteratorComplet est iterator :", hasattr(i2, "__next__"))
```
