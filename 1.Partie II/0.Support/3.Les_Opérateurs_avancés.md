- Rendre le code plus naturel

# 3️⃣ Exemple métier : Vecteur 2D

Nous allons modéliser un vecteur scientifique.

Objectifs :

- Addition

- Soustraction

- Multiplication scalaire

- Comparaison

- Affichage propre

---

## Définition propre et commentée

```python
class Vecteur:

    # Constructeur avec validation
    def __init__(self, x: float, y: float):

        # Vérification des types
        if not isinstance(x, (int, float)) or not isinstance(y, (int, float)):
            raise TypeError("Les coordonnées doivent être numériques")

        self.x = float(x)
        self.y = float(y)

    # Représentation développeur
    def __repr__(self):
        return f"Vecteur(x={self.x}, y={self.y})"

    # Addition vectorielle
    def __add__(self, autre):

        # Vérification du type
        if not isinstance(autre, Vecteur):
            raise TypeError("Addition uniquement entre vecteurs")

        return Vecteur(self.x + autre.x, self.y + autre.y)

    # Soustraction vectorielle
    def __sub__(self, autre):

        if not isinstance(autre, Vecteur):
            raise TypeError("Soustraction uniquement entre vecteurs")

        return Vecteur(self.x - autre.x, self.y - autre.y)

    # Multiplication par un scalaire
    def __mul__(self, scalaire):

        if not isinstance(scalaire, (int, float)):
            raise TypeError("Multiplication uniquement par un nombre")

        return Vecteur(self.x * scalaire, self.y * scalaire)

    # Opérateur reflété (3 * vecteur)
    def __rmul__(self, scalaire):
        return self.__mul__(scalaire)

    # Comparaison stricte
    def __eq__(self, autre):

        if not isinstance(autre, Vecteur):
            return False

        return self.x == autre.x and self.y == autre.y

    # Norme du vecteur
    def norme(self):
        return (self.x**2 + self.y**2) ** 0.5

    # Comparaison basée sur la norme
    def __lt__(self, autre):

        if not isinstance(autre, Vecteur):
            raise TypeError("Comparaison uniquement entre vecteurs")

        return self.norme() < autre.norme()
```

---

## Démonstration observable

```python
v1 = Vecteur(2, 3)
v2 = Vecteur(4, 1)

print("Addition :", v1 + v2)
print("Soustraction :", v1 - v2)
print("Multiplication :", v1 * 3)
print("Multiplication reflétée :", 3 * v1)
print("Comparaison égalité :", v1 == Vecteur(2, 3))
print("Comparaison norme :", v1 < Vecteur(5, 5))
```

# 5️⃣ Exemple métier : Matrice 2x2

Objectif :

- Addition sécurisée

- Validation dimensionnelle

- Représentation propre

---

## Implémentation rigoureuse

```python
class Matrice2x2:

    def __init__(self, valeurs):

        # Validation structure
        if len(valeurs) != 2 or any(len(ligne) != 2 for ligne in valeurs):
            raise ValueError("Matrice 2x2 attendue")

        self.valeurs = [
            [float(valeurs[i][j]) for j in range(2)]
            for i in range(2)
        ]

    def __repr__(self):
        return f"Matrice2x2({self.valeurs})"

    def __add__(self, autre):

        if not isinstance(autre, Matrice2x2):
            raise TypeError("Addition uniquement entre matrices")

        resultat = [
            [
                self.valeurs[i][j] + autre.valeurs[i][j]
                for j in range(2)
            ]
            for i in range(2)
        ]

        return Matrice2x2(resultat)

    def __eq__(self, autre):
        return isinstance(autre, Matrice2x2) and self.valeurs == autre.valeurs
```

---

## Démonstration

```python
m1 = Matrice2x2([[1, 2], [3, 4]])
m2 = Matrice2x2([[5, 6], [7, 8]])

print("Addition matrices :", m1 + m2)
print("Comparaison :", m1 == Matrice2x2([[1, 2], [3, 4]]))
```

# 1️⃣ Pourquoi retourner NotImplemented plutôt que lever TypeError ?

## Énoncé

Pourquoi certaines méthodes d’opérateurs doivent retourner NotImplemented au lieu de lever une exception ?

## Solution

```python
"""
Explication :

Lorsqu'un opérateur ne sait pas gérer le type reçu,
il est préférable de retourner NotImplemented.

Cela permet à Python d’essayer l’opérateur reflété
chez l’autre objet avant de lever une exception.
"""

class A:

    def __add__(self, other):

        # Si type incompatible, on retourne NotImplemented
        if not isinstance(other, A):
            return NotImplemented

        return "Addition A"


class B:

    def __radd__(self, other):
        return "Addition via B"


a = A()
b = B()

print(a + b)  # Python tente A.__add__, puis B.__radd__
```

# 3️⃣ Différence entre **add** et **iadd**

## Énoncé

Pourquoi += ne se comporte pas toujours comme + ?

## Solution

```python
"""
Explication :

__add__ crée un nouvel objet.
__iadd__ modifie l'objet existant.

Si __iadd__ n'existe pas,
Python utilise __add__.
"""

class Compteur:

    def __init__(self, valeur):
        self.valeur = valeur

    def __add__(self, other):
        return Compteur(self.valeur + other)

    def __iadd__(self, other):
        self.valeur += other
        return self


c = Compteur(10)

c += 5

print(c.valeur)
```

# 4️⃣ Pourquoi 3 * vecteur échoue sans **rmul** ?

## Énoncé

Pourquoi l’ordre des opérandes influence l’appel de méthode ?

## Solution

```python
"""
Explication :

Python appelle d’abord int.__mul__(vecteur).
Si cela échoue,
il appelle vecteur.__rmul__(int).
"""

class Vecteur:

    def __init__(self, x):
        self.x = x

    def __mul__(self, other):
        return Vecteur(self.x * other)

    def __rmul__(self, other):
        return self.__mul__(other)


v = Vecteur(5)

print(3 * v)
```

# 5️⃣ Pourquoi comparer des floats avec == est dangereux ?

# 7️⃣ Pourquoi **eq** impacte **hash** ?

## Énoncé

Pourquoi un objet devient parfois inutilisable comme clé de dictionnaire ?

## Solution

```python
"""
Explication :

Si __eq__ est redéfini,
Python supprime automatiquement __hash__.

Il faut le redéfinir pour conserver la cohérence.
"""

class Point:

    def __init__(self, x):
        self.x = x

    def __eq__(self, other):
        return isinstance(other, Point) and self.x == other.x

    def __hash__(self):
        return hash(self.x)


p1 = Point(5)
p2 = Point(5)

d = {p1: "valeur"}

print(d[p2])
```

# 14️⃣ Ordre exact de résolution des opérateurs

## Énoncé

Quel est l’ordre exact suivi par Python lorsqu’on exécute objet1 + objet2 ?

## Solution

```python
"""
Explication :

Lorsqu’on exécute objet1 + objet2,
Python suit l’ordre suivant :

1) objet1.__add__(objet2)
2) Si retourne NotImplemented → objet2.__radd__(objet1)
3) Si toujours non géré → TypeError

Nous allons illustrer ce mécanisme.
"""

class A:

    def __add__(self, other):
        print("Appel de A.__add__")
        return NotImplemented


class B:

    def __radd__(self, other):
        print("Appel de B.__radd__")
        return "Résolution via B"


a = A()
b = B()

resultat = a + b

print("Résultat :", resultat)
```

Conclusion :  
Python tente d’abord **add**, puis **radd**.

# 15️⃣ Pourquoi éviter la mutation dans **add** ?

## Énoncé

Pourquoi modifier self dans **add** est une mauvaise pratique ?

## Solution

```python
"""
Explication :

__add__ doit retourner un nouvel objet.

Si on modifie self,
on casse l’immuabilité logique
et le comportement devient imprévisible.
"""

class MauvaisVecteur:

    def __init__(self, x):
        self.x = x

    def __add__(self, other):

        # Mutation directe
        self.x += other.x
        return self


v1 = MauvaisVecteur(5)
v2 = MauvaisVecteur(3)

v3 = v1 + v2

print("v1.x :", v1.x)
print("v3.x :", v3.x)
```

Analyse :  
v1 est modifié → effet de bord dangereux.

Version correcte :

```python
class BonVecteur:

    def __init__(self, x):
        self.x = x

    def __add__(self, other):
        return BonVecteur(self.x + other.x)


v1 = BonVecteur(5)
v2 = BonVecteur(3)

v3 = v1 + v2

print("v1.x :", v1.x)
print("v3.x :", v3.x)
```

Conclusion :  
Toujours retourner un nouvel objet.

# 16️⃣ Shallow copy vs Deep copy

## Énoncé

Pourquoi une copie superficielle peut créer des effets inattendus ?

## Solution

```python
"""
Explication :

Une copie superficielle copie uniquement
le conteneur principal.

Les sous-objets restent partagés.

Deepcopy copie toute la structure.
"""

import copy


class Conteneur:

    def __init__(self, valeurs):
        self.valeurs = valeurs


original = Conteneur([[1, 2], [3, 4]])

copie_superficielle = copy.copy(original)
copie_profonde = copy.deepcopy(original)

# Modification interne
copie_superficielle.valeurs[0].append(99)

print("Original :", original.valeurs)
print("Superficielle :", copie_superficielle.valeurs)
print("Profonde :", copie_profonde.valeurs)
```

Conclusion :  
Deepcopy protège contre les effets de bord.

# 17️⃣ Pourquoi implémenter toutes les comparaisons ?

## Énoncé

Pourquoi définir seulement **lt** peut être insuffisant ?

## Solution

```python
"""
Explication :

Si seule __lt__ est définie,
les autres opérateurs (<=, >, >=)
ne sont pas automatiquement disponibles.

On peut utiliser functools.total_ordering
pour générer les autres méthodes.
"""

from functools import total_ordering


@total_ordering
class Score:

    def __init__(self, valeur):
        self.valeur = valeur

    def __eq__(self, other):
        return self.valeur == other.valeur

    def __lt__(self, other):
        return self.valeur < other.valeur


s1 = Score(10)
s2 = Score(20)

print("s1 < s2 :", s1 < s2)
print("s1 <= s2 :", s1 <= s2)
print("s1 > s2 :", s1 > s2)
```

Conclusion :  
total_ordering évite la duplication.

# 18️⃣ Pourquoi typer les opérateurs ?

Pourquoi ajouter des annotations de type améliore la robustesse ?

## Solution

```python
"""
Explication :

Les annotations permettent :

- Détection statique d’erreurs
- Meilleure documentation
- Meilleur support IDE

Nous allons illustrer avec une surcharge typée.
```

# 19️⃣ Impact performance surcharge massive

## Énoncé

Une surcharge d’opérateur a-t-elle un coût réel ?

## Solution

```python
"""
Explication :

Chaque opérateur surchargé
est un appel de méthode.

Nous comparons un calcul direct
avec un calcul via surcharge.
"""

import time


class Nombre:

    def __init__(self, valeur):
        self.valeur = valeur

    def __add__(self, other):
        return Nombre(self.valeur + other.valeur)


# Test natif
start = time.time()

x = 0
for i in range(1_000_000):
    x = x + 1

fin = time.time()
print("Temps natif :", fin - start)


# Test surcharge
start = time.time()

n = Nombre(0)
for i in range(1_000_000):
    n = n + Nombre(1)

fin = time.time()
print("Temps surcharge :", fin - start)
```
