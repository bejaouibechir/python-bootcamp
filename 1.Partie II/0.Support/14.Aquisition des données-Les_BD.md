# 2️⃣ Connexion à SQLite

SQLite est intégré à Python via le module sqlite3.

## Cas métier

Un micro-service local doit stocker des logs d’activité sans dépendre d’un serveur externe.

---

## Exemple complet commenté

```python
"""
Connexion à une base SQLite locale.
- Si le fichier n'existe pas, il est créé automatiquement.
- SQLite fonctionne en mode fichier.
"""

import sqlite3

# Connexion à une base locale
conn = sqlite3.connect("exemple.db")

# Création d'un curseur (interface d'exécution SQL)
cursor = conn.cursor()

# Création d'une table si elle n'existe pas
cursor.execute("""
CREATE TABLE IF NOT EXISTS utilisateur (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    nom TEXT NOT NULL,
    age INTEGER NOT NULL
)
""")

# Insertion sécurisée avec paramètres (évite injection SQL)
cursor.execute(
    "INSERT INTO utilisateur (nom, age) VALUES (?, ?)",
    ("Bechir", 40)
)

# Validation transaction
conn.commit()

# Lecture des données
cursor.execute("SELECT * FROM utilisateur")
resultats = cursor.fetchall()

print("Contenu table utilisateur:")
for ligne in resultats:
    print(ligne)

# Fermeture propre
cursor.close()
conn.close()
```

---

## Points essentiels

- Toujours utiliser des paramètres ? pour éviter injection SQL.

- Toujours appeler commit() après modification.

- Toujours fermer connexion et curseur.

- Utiliser with sqlite3.connect(...) pour gestion automatique.

# 3️⃣ Connexion à MySQL

Bibliothèque recommandée : mysql-connector-python.

Installation préalable :

pip install mysql-connector-python

---

## Cas métier

Une application e-commerce doit se connecter à un serveur MySQL distant.

---

## Exemple structuré

```python
"""
Connexion à MySQL.
- Connexion serveur distant.
- Gestion d'erreur.
- Insertion sécurisée.
"""

import mysql.connector
from mysql.connector import Error

try:
    # Connexion au serveur MySQL
    conn = mysql.connector.connect(
        host="localhost",
        user="root",
        password="password",
        database="testdb"
    )

    if conn.is_connected():
        print("Connexion MySQL réussie")

        cursor = conn.cursor()

        # Création table
        cursor.execute("""
        CREATE TABLE IF NOT EXISTS produit (
            id INT AUTO_INCREMENT PRIMARY KEY,
            nom VARCHAR(100),
            prix DECIMAL(10,2)
        )
        """)

        # Insertion sécurisée
        sql = "INSERT INTO produit (nom, prix) VALUES (%s, %s)"
        valeurs = ("Clavier", 99.90)
        cursor.execute(sql, valeurs)

        conn.commit()

        # Lecture
        cursor.execute("SELECT * FROM produit")
        for row in cursor.fetchall():
            print(row)

except Error as e:
    print("Erreur MySQL:", e)

finally:
    if 'conn' in locals() and conn.is_connected():
        cursor.close()
        conn.close()
        print("Connexion fermée")
```

---

## Bonnes pratiques MySQL

- Ne jamais concaténer les variables dans la requête.

- Utiliser %s comme placeholder.

- Gérer les exceptions Error.

- Vérifier conn.is_connected().

---

## Cas métier

Un système financier doit interagir avec PostgreSQL pour sa robustesse transactionnelle.

---

## Exemple complet

```python
"""
Connexion à PostgreSQL avec gestion transaction.
"""

import psycopg2
from psycopg2 import OperationalError

try:
    conn = psycopg2.connect(
        host="localhost",
        database="testdb",
        user="postgres",
        password="password",
        port="5432"
    )

    cursor = conn.cursor()

    print("Connexion PostgreSQL réussie")

    # Création table
    cursor.execute("""
    CREATE TABLE IF NOT EXISTS client (
        id SERIAL PRIMARY KEY,
        nom VARCHAR(100),
        email VARCHAR(100)
    )
    """)

    # Insertion
    cursor.execute(
        "INSERT INTO client (nom, email) VALUES (%s, %s)",
        ("Alice", "alice@email.com")
    )

    conn.commit()

    # Lecture
    cursor.execute("SELECT * FROM client")
    rows = cursor.fetchall()

    print("Clients:")
    for row in rows:
        print(row)

except OperationalError as e:
    print("Erreur PostgreSQL:", e)

finally:
    if 'conn' in locals():
        cursor.close()
        conn.close()
        print("Connexion fermée")
```

# 5️⃣ Transactions : Compréhension fondamentale

Toutes les bases relationnelles fonctionnent avec :

- BEGIN

- COMMIT

- ROLLBACK

---

## Exemple transaction PostgreSQL

```python
"""
Simulation d'une transaction bancaire.
- Si une erreur survient, rollback.
"""

import psycopg2

conn = psycopg2.connect(
    host="localhost",
    database="testdb",
    user="postgres",
    password="password"
)

cursor = conn.cursor()

try:
    cursor.execute("UPDATE compte SET solde = solde - 100 WHERE id = 1")
    cursor.execute("UPDATE compte SET solde = solde + 100 WHERE id = 2")

    # Simulation erreur
    raise Exception("Erreur simulée")

    conn.commit()

except Exception as e:
    print("Erreur détectée:", e)
    conn.rollback()
    print("Rollback effectué")

finally:
    cursor.close()
    conn.close()
```

# 6️⃣ Base DAO

Créer le fichier **app/dao/base_dao.py** :

```python
"""
BaseDAO: utilitaires communs.
- Ouvre et ferme la connexion proprement.
- Fournit un cadre transactionnel.
"""

from contextlib import contextmanager
from app.db.db_factory import get_connection


class BaseDAO:

    @contextmanager
    def _session(self):
        """
        Gestion transactionnelle.
        - Commit si tout passe.
        - Rollback si exception.
        """
        conn = get_connection()
        try:
            yield conn
            conn.commit()
        except Exception:
            conn.rollback()
            raise
        finally:
            conn.close()
```

# 7️⃣ DAO Client

Créer le fichier **app/dao/client_dao.py** :

```python
"""
ClientDAO: accès base de données pour la table client.

Schéma table:
- SQLite: id INTEGER PRIMARY KEY AUTOINCREMENT
- MySQL: id INT AUTO_INCREMENT PRIMARY KEY
- PostgreSQL: id SERIAL PRIMARY KEY

Pour rester portable, on ne met pas de syntaxe spécifique à un moteur.
"""

from app.dao.base_dao import BaseDAO


class ClientDAO(BaseDAO):

    def create_table_if_needed(self):
        """
        Création table portable.
        - Attention: type auto-increment varie selon moteurs.
        - Ici on utilise un SQL minimal compatible.
        """
        sql = """
        CREATE TABLE IF NOT EXISTS client (
            id INTEGER PRIMARY KEY,
            nom VARCHAR(100) NOT NULL,
            email VARCHAR(100) NOT NULL
        )
        """
        with self._session() as conn:
            cur = conn.cursor()
            cur.execute(sql)

    def insert(self, nom, email):
        """
        Insertion sécurisée via paramètres.
        """
        sql = "INSERT INTO client (nom, email) VALUES (%s, %s)"

        with self._session() as conn:
            cur = conn.cursor()

            # SQLite utilise ? au lieu de %s
            if conn.__class__.__module__.startswith("sqlite3"):
                sql = "INSERT INTO client (nom, email) VALUES (?, ?)"

            cur.execute(sql, (nom, email))

    def get_all(self):
        """
        Lecture simple.
        """
        with self._session() as conn:
            cur = conn.cursor()
            cur.execute("SELECT id, nom, email FROM client ORDER BY id DESC")
            return cur.fetchall()

    def delete_by_id(self, client_id):
        """
        Suppression par ID.
        """
        sql = "DELETE FROM client WHERE id = %s"

        with self._session() as conn:
            cur = conn.cursor()

            if conn.__class__.__module__.startswith("sqlite3"):
                sql = "DELETE FROM client WHERE id = ?"

            cur.execute(sql, (client_id,))
```

# 8️⃣ Couche Service

Créer le fichier **app/services/client_service.py** :

```python
"""
Couche Service:
- Contient la logique métier.
- Ne contient pas de SQL.
- Appelle le DAO.

from app.dao.client_dao import ClientDAO


class ClientService:

    def __init__(self):
        self.dao = ClientDAO()

    def init_storage(self):
        self.dao.create_table_if_needed()

    def ajouter_client(self, nom, email):
        if "@" not in email:
            raise ValueError("Email invalide")
        self.dao.insert(nom, email)

    def lister_clients(self):
        return self.dao.get_all()

    def supprimer_client(self, client_id):
        self.dao.delete_by_id(client_id)
```

# 9️⃣ Programme principal de démonstration

Créer le fichier **app/main.py** :

```python
"""
Démo complète:
- Initialisation table
- Insertion
- Lecture
- Suppression
- Affichage observable
"""

from app.services.client_service import ClientService


def afficher_clients(clients):
    print("Liste clients:")
    for row in clients:
        # row peut être tuple ou sqlite Row
        try:
            print(f"{row['id']} | {row['nom']} | {row['email']}")
        except Exception:
            print(f"{row[0]} | {row[1]} | {row[2]}")


def main():
    service = ClientService()

    # Init table
    service.init_storage()

    # Ajout clients
    service.ajouter_client("Alice", "alice@email.com")
    service.ajouter_client("Bob", "bob@email.com")

    # Affichage
    clients = service.lister_clients()
    afficher_clients(clients)

    # Suppression du dernier client
    if clients:
        last_id = None
        try:
            last_id = clients[0]["id"]
        except Exception:
            last_id = clients[0][0]

        service.supprimer_client(last_id)
        print(f"Client supprimé: {last_id}")

    # Affichage final
    clients = service.lister_clients()
    afficher_clients(clients)


if __name__ == "__main__":
    main()
```

# 1) Pourquoi commit() est-il obligatoire après INSERT ?

## Énoncé

Pourquoi les données semblent insérées mais disparaissent après fermeture de connexion ?

## Solution

```python
"""
Explication :
Dans la plupart des moteurs relationnels, les modifications sont placées dans une transaction.
Sans commit(), elles ne sont pas persistées.
SQLite peut parfois donner l’illusion que cela fonctionne, mais en réalité la transaction n’est pas validée.
"""

import sqlite3

conn = sqlite3.connect("test_commit.db")
cursor = conn.cursor()

cursor.execute("CREATE TABLE IF NOT EXISTS test (id INTEGER PRIMARY KEY, nom TEXT)")
cursor.execute("INSERT INTO test (nom) VALUES (?)", ("Alice",))

# conn.commit() volontairement omis

cursor.close()
conn.close()

# Nouvelle connexion pour vérifier
conn = sqlite3.connect("test_commit.db")
cursor = conn.cursor()
cursor.execute("SELECT * FROM test")
print("Contenu après fermeture sans commit:", cursor.fetchall())

cursor.close()
conn.close()
```

Observation : les données ne sont pas persistées.

# 2) Pourquoi ne jamais concaténer une variable dans une requête SQL ?

## Énoncé

Quel est le risque si on écrit :

SELECT * FROM client WHERE nom = '" + nom + "' ?

## Solution

```python
"""
Explication :
Concaténer une variable ouvre la porte aux injections SQL.
Les paramètres sécurisés empêchent l'exécution de code malveillant.
"""

import sqlite3

conn = sqlite3.connect(":memory:")
cursor = conn.cursor()

cursor.execute("CREATE TABLE client (id INTEGER PRIMARY KEY, nom TEXT)")
cursor.execute("INSERT INTO client (nom) VALUES (?)", ("Alice",))
conn.commit()

# Simulation injection
nom = "' OR 1=1 --"

requete_dangereuse = "SELECT * FROM client WHERE nom = '" + nom + "'"
print("Requête dangereuse:", requete_dangereuse)

cursor.execute(requete_dangereuse)
print("Résultat injection:", cursor.fetchall())

# Version sécurisée
cursor.execute("SELECT * FROM client WHERE nom = ?", (nom,))
print("Résultat sécurisé:", cursor.fetchall())

cursor.close()
conn.close()
```

# 3) Pourquoi faut-il gérer rollback() ?

## Énoncé

Que se passe-t-il si une erreur survient entre deux UPDATE ?

## Solution

```python
"""
Explication :
Sans rollback(), la base peut rester dans un état incohérent.
Une transaction doit être atomique.
"""

import sqlite3

conn = sqlite3.connect(":memory:")
cursor = conn.cursor()

cursor.execute("CREATE TABLE compte (id INTEGER PRIMARY KEY, solde INTEGER)")
cursor.execute("INSERT INTO compte VALUES (1, 1000)")
cursor.execute("INSERT INTO compte VALUES (2, 500)")
conn.commit()

try:
    cursor.execute("UPDATE compte SET solde = solde - 100 WHERE id = 1")
    raise Exception("Erreur simulée")
    cursor.execute("UPDATE compte SET solde = solde + 100 WHERE id = 2")
    conn.commit()
except Exception:
    conn.rollback()
    print("Rollback effectué")

cursor.execute("SELECT * FROM compte")
print("État final:", cursor.fetchall())

cursor.close()
conn.close()
```

# 4) Différence entre fetchone() et fetchall() ?

## Énoncé

Quand utiliser l’un ou l’autre ?

## Solution

```python
"""
Explication :
fetchone() récupère une seule ligne.
fetchall() charge tout en mémoire.
Pour gros volumes, fetchone() est plus sûr.
"""

import sqlite3

conn = sqlite3.connect(":memory:")
cursor = conn.cursor()

cursor.execute("CREATE TABLE test (id INTEGER)")
cursor.executemany("INSERT INTO test VALUES (?)", [(1,), (2,), (3,)])
conn.commit()

cursor.execute("SELECT * FROM test")
print("fetchone:", cursor.fetchone())

cursor.execute("SELECT * FROM test")
print("fetchall:", cursor.fetchall())

cursor.close()
conn.close()
```

# 5) Pourquoi utiliser row_factory avec SQLite ?

## Énoncé

Comment accéder aux colonnes par nom plutôt que par index ?

## Solution

```python
"""
Explication :
row_factory = sqlite3.Row permet d’accéder aux colonnes par clé.
Plus lisible et robuste.
"""

import sqlite3

conn = sqlite3.connect(":memory:")
conn.row_factory = sqlite3.Row
cursor = conn.cursor()

cursor.execute("CREATE TABLE client (id INTEGER, nom TEXT)")
cursor.execute("INSERT INTO client VALUES (?, ?)", (1, "Alice"))
conn.commit()

cursor.execute("SELECT * FROM client")
row = cursor.fetchone()

print("Accès par index:", row[1])
print("Accès par nom:", row["nom"])

cursor.close()
conn.close()
```
