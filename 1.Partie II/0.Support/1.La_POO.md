# 1️⃣ Pourquoi la POO ?

La POO permet de :

- Structurer un programme complexe

- Modéliser des entités réelles

- Réduire le couplage

- Améliorer la maintenabilité

- Faciliter les tests

Exemple réel :  
Un système RH, une boutique en ligne, un ERP…  
Tout est composé d’objets (Employé, Client, Produit, Commande).

# 2️⃣ Classe vs Objet

## Définition

- **Classe** → Plan de construction

- **Objet (instance)** → Élément concret créé à partir du plan

---

## Exemple propre et commenté

```python
# Définition d'une classe représentant une personne
class Personne:

    # Constructeur appelé automatiquement lors de la création d'une instance
    def __init__(self, nom: str, age: int):
        self.nom = nom        # Attribut d'instance
        self.age = age        # Attribut d'instance

    # Méthode d'instance
    def afficher(self):
        print(f"Nom: {self.nom}, Age: {self.age}")
```

```python
# Création d'un objet
p1 = Personne("Bechir", 40)

# Appel d'une méthode
p1.afficher()
```

# 3️⃣ Encapsulation

En Python, il n’existe pas d’encapsulation stricte comme en Java.

On distingue :

- Public → nom

- Protégé (convention) → _nom

- Privé (name mangling) → __nom

---

## Exemple rigoureux

```python
class CompteBancaire:

    def __init__(self, titulaire: str, solde: float):
        self.titulaire = titulaire
        self.__solde = solde   # Attribut privé

    def deposer(self, montant: float):
        self.__solde += montant

    def consulter_solde(self):
        return self.__solde
```

```python
compte = CompteBancaire("Bechir", 1000)
compte.deposer(500)

print(compte.consulter_solde())
```

Tentative d’accès direct :

```python
compte.__solde  # Provoque une erreur
```

⚠ Le name mangling ne protège pas réellement, mais empêche l’accès accidentel.

# 4️⃣ Héritage

Permet de réutiliser le code d’une classe mère.

---

## Exemple métier : système RH

```python
class Employe:

    def __init__(self, nom: str, salaire: float):
        self.nom = nom
        self.salaire = salaire

    def afficher(self):
        print(f"Employé: {self.nom}, Salaire: {self.salaire}")
```

```python
class Manager(Employe):

    def __init__(self, nom: str, salaire: float, equipe: int):
        super().__init__(nom, salaire)  # Bonne pratique moderne
        self.equipe = equipe

    def afficher(self):
        super().afficher()
        print(f"Taille équipe: {self.equipe}")
```

# 5️⃣ Polymorphisme

Même méthode → comportement différent.

```python
class Animal:

```

```python
class Chien(Animal):

```

```python

    def parler(self):
        print("Le chat miaule")
```

```python
animaux = [Chien(), Chat()]

for animal in animaux:
    animal.parler()
```

Le programme ne se soucie pas du type exact → principe ouvert/fermé.

```python
Explication
- Attribut de classe: défini dans la classe, partagé par toutes les instances.
```

# 3) Pourquoi super() est préférable à ClasseMere.**init** ?

## Énoncé

Pourquoi super() est recommandé, surtout en cas d’héritage multiple ?

## Solution

```python
"""
Explication
- super() respecte l’ordre MRO (Method Resolution Order).
- Il permet une initialisation en chaîne correcte si plusieurs parents existent.
- Appeler directement Parent.__init__() casse souvent la chaîne en héritage multiple.
"""

class A:
    def __init__(self):
        print("Init A")

class B(A):
    def __init__(self):
        super().__init__()
        print("Init B")

b = B()
```

# 4) Attribut privé : est-il vraiment privé ?

## Énoncé

En Python, un attribut avec double underscore est-il inaccessible ? Pourquoi ?

## Solution

```python
"""
Explication
- __x déclenche le name mangling: Python renomme en _NomDeClasse__x.
- Ce n’est pas une sécurité, mais une protection contre l’accès accidentel.
"""

class Coffre:
    def __init__(self):
        self.__code = 1234

c = Coffre()

# Accès direct: erreur (normal)
try:
    print(c.__code)
except AttributeError as e:
    print("Accès direct impossible:", e)

# Accès via name mangling: possible (intermédiaire)
print("Accès réel:", c._Coffre__code)
```

# 5) @classmethod vs @staticmethod

## Énoncé

Quand utiliser une méthode de classe plutôt qu’une méthode statique ?

## Solution

```python
"""
Explication
- classmethod reçoit la classe (cls), utile pour factory, config, héritage.
- staticmethod ne reçoit ni self ni cls, utile pour utilitaires liés à la classe.
"""

class Config:
    version = "1.0"

    @classmethod
    def afficher_version(cls):
        print("Version via cls:", cls.version)

    @staticmethod
    def outil():
        print("Outil statique: pas d’accès automatique à cls ou self")

Config.afficher_version()
Config.outil()
```

# 6) Héritage multiple : comment Python choisit la méthode ?

## Énoncé

Si deux parents possèdent la même méthode, laquelle sera appelée ?

## Solution

```python
"""
Explication
- Python suit le MRO: ordre de résolution des méthodes.
- Dans class C(A, B), Python cherche d’abord dans C, puis A, puis B.
"""

class A:
    def action(self):
        print("Action A")

class B:
    def action(self):
        print("Action B")

class C(A, B):
    pass

C().action()
print("MRO:", [cls.__name__ for cls in C.mro()])
```

# 7) Problème diamant : super() fonctionne-t-il vraiment ?

## Énoncé

Dans un héritage en diamant, comment éviter d’appeler deux fois le même parent ?

## Solution

```python
"""
Explication
- Le diamant: D hérite de B et C qui héritent de A.
- super() + MRO permet d’appeler A une seule fois, si tout le monde utilise super().
"""

class A:
    def __init__(self):
        print("Init A")

class B(A):
    def __init__(self):
        super().__init__()
        print("Init B")

class C(A):
    def __init__(self):
        super().__init__()
        print("Init C")

class D(B, C):
    def __init__(self):
        super().__init__()
        print("Init D")

D()
print("MRO:", [cls.__name__ for cls in D.mro()])
```

# 8) Valeurs par défaut mutables : pourquoi c’est dangereux ?

## Énoncé

Pourquoi une liste en valeur par défaut peut provoquer des bugs ?

## Solution

```python
"""
Explication
- Une valeur par défaut est évaluée une seule fois à la définition de la fonction.
- Donc la même liste est partagée entre tous les appels.
- Solution: utiliser None, puis créer une nouvelle liste.
"""

class PanierMauvais:
    def __init__(self, items=[]):
        self.items = items

p1 = PanierMauvais()
p2 = PanierMauvais()

p1.items.append("X")
print("p1:", p1.items)
print("p2:", p2.items, "-> bug: partagé")

class PanierCorrect:
    def __init__(self, items=None):
        if items is None:
            items = []
        self.items = items

q1 = PanierCorrect()
q2 = PanierCorrect()

q1.items.append("Y")
print("q1:", q1.items)
print("q2:", q2.items, "-> correct: indépendant")
```

# 9) isinstance() vs type() : pourquoi ça change tout ?

## Énoncé

Quand type(obj) == Classe est une mauvaise idée ?

## Solution

```python
"""
Explication
- type(obj) == Classe teste uniquement le type exact.
- isinstance(obj, Classe) accepte aussi les sous-classes.
- En POO, isinstance est souvent le bon choix.
"""

class A:
    pass

class B(A):
    pass

b = B()

print("type exact:", type(b) == B)
print("type exact vs parent:", type(b) == A)
print("isinstance parent:", isinstance(b, A))
print("isinstance enfant:", isinstance(b, B))
```

# 10) **str** vs **repr** : quand utiliser lequel ?

## Énoncé

Quelle différence entre affichage utilisateur et représentation développeur ?

## Solution

```python
"""
Explication
- __str__ est destiné à un affichage lisible (utilisateur).
- __repr__ est destiné au debugging (développeur), plus précis.
"""

class Produit:
    def __init__(self, nom, prix):
        self.nom = nom
        self.prix = prix

    def __str__(self):
        return f"{self.nom} - {self.prix} TND"

    def __repr__(self):
        return f"Produit(nom={self.nom!r}, prix={self.prix!r})"

p = Produit("Clavier", 99.9)

print("str:", str(p))
print("repr:", repr(p))
print("print(obj):", p)
```

# 11) Propriété property : pourquoi c’est mieux qu’un getter/setter ?

## Énoncé

Pourquoi property est plus pythonique que get_age/set_age ?

## Solution

```python
"""
Explication
- property permet un accès en attribut tout en gardant une logique de validation.
- Le code utilisateur reste simple: obj.age au lieu de obj.get_age().
"""

class Personne:
    def __init__(self, age):
        self._age = age

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, valeur):
        if valeur < 0:
            raise ValueError("Age invalide")
        self._age = valeur

p = Personne(20)
print("Age:", p.age)

p.age = 25
print("Age:", p.age)

try:
    p.age = -1
except ValueError as e:
    print("Erreur:", e)
```

# 14) ABC : comment forcer une méthode à être implémentée ?

## Énoncé

Comment empêcher l’instanciation d’une classe si une méthode obligatoire manque ?

## Solution

```python
"""
Explication
- Une classe abstraite définit un contrat.
- Les sous-classes doivent implémenter les méthodes abstractmethod.
"""

from abc import ABC, abstractmethod

class Paiement(ABC):

    @abstractmethod
    def payer(self, montant: float):
        pass

class Carte(Paiement):
    def payer(self, montant: float):
        print(f"Paiement carte: {montant}")

c = Carte()
c.payer(100)
```

# 16) **slots** : pourquoi et quand l’utiliser ?

## Énoncé

Comment réduire mémoire et empêcher la création dynamique d’attributs ?

## Solution

```python
"""
Explication
- __slots__ limite les attributs autorisés.
- Empêche obj.nouvel_attribut = ...
- Peut réduire la consommation mémoire pour énormément d’objets.
"""

class Point:
    __slots__ = ("x", "y")

        self.y = y

p = Point(1, 2)
print("p.x:", p.x)

try:
    p.z = 3

    print("Erreur:", e)
```

# 17) Pourquoi la composition est souvent meilleure que l’héritage ?

Donnez un exemple simple où l’héritage serait une mauvaise modélisation.

## Solution

```python
"""
Explication
```

# 18) shallow copy vs deep copy : piège fréquent en POO

## Énoncé

Pourquoi copier une liste de listes peut produire des effets surprises ?

## Solution

```python
"""
Explication
- Copie superficielle: copie la liste principale, mais garde les mêmes sous-listes.
- Copie profonde: copie tout récursivement.
"""

import copy

a = [[1, 2], [3, 4]]
b = list(a)           # shallow
c = copy.deepcopy(a)  # deep

b[0].append(99)

print("a:", a, "-> modifié via shallow")
print("b:", b)
print("c:", c, "-> intact")
```

# 19) Méthode spéciale **call** : pourquoi c’est utile ?

Comment rendre un objet appelable comme une fonction ?

## Solution

```python
"""
Explication
- __call__ permet d’appeler un objet comme une fonction.
- Utile pour stratégies, callbacks, objets configurés.
"""
```

# 20) **new** vs **init** : différence souvent floue

## Énoncé

À quoi sert **new** et quand est-il utilisé ?

## Solution

```python
"""
Explication
- __new__ crée l’objet (allocation). Il est appelé avant __init__.
- __init__ initialise l’objet déjà créé.
- __new__ est utile pour singletons, immutables, contrôle de création.
"""

class Demo:
    def __new__(cls, *args, **kwargs):
        print("__new__ -> création")
        return super().__new__(cls)

    def __init__(self):
        print("__init__ -> initialisation")

Demo()
```
