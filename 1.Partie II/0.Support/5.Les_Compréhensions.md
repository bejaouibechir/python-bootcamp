# 7️⃣ Générateurs — Gestion de gros volumes

## Contexte

Simulation de 10 millions de transactions.

---

Créer le fichier **transactions_generateur.py** :

```python
"""
Objectif
Produire des valeurs à la demande.

Principe
yield suspend l'exécution et retourne une valeur.
Aucune liste complète n’est stockée en mémoire.
"""

def generer_transactions():
    for i in range(10_000_000):
        if i % 2 == 0:
            yield i   # production paresseuse

transactions = generer_transactions()

print("Type :", type(transactions))

# Consommation progressive
for _ in range(5):
    print(next(transactions))
```

## 1) Pourquoi un générateur affiche un objet au lieu des valeurs ?

Créer le fichier **q01_generateur_affichage.py** :

```python
"""
Objectif
Comprendre pourquoi un générateur n’affiche pas ses valeurs directement.

Idée
- Un générateur est un objet paresseux.
- Il produit des valeurs uniquement quand on le consomme (for, next, list, sum...).
- Afficher le générateur affiche l’objet, pas son contenu.
"""

def multiples_de_trois(valeurs):
    for v in valeurs:
        if v % 3 == 0:
            yield v

data = range(1, 21)

gen = multiples_de_trois(data)

print("Affichage direct du générateur :", gen)

print("Consommation avec next :")
print(next(gen))
print(next(gen))

print("Consommation du reste avec for :")
for x in gen:
    print(x)
```

## 4) Pourquoi une compréhension est souvent plus rapide qu’un for + append ?

Créer le fichier **q04_perf_listcomp.py** :

```python
"""
Objectif
Montrer une mesure simple : liste via for vs compréhension.

Idée
- La compréhension est optimisée côté CPython (boucle interne plus rapide).
- On mesure sur une taille raisonnable.
"""

import time

n = 500000

t0 = time.perf_counter()
res1 = []
for i in range(n):
    if i % 3 == 0:
        res1.append(i * 2)
t1 = time.perf_counter()

t2 = time.perf_counter()
res2 = [i * 2 for i in range(n) if i % 3 == 0]
t3 = time.perf_counter()

print("Même résultat :", res1[:5] == res2[:5] and len(res1) == len(res2))
print("for+append :", round(t1 - t0, 4), "s")
print("listcomp  :", round(t3 - t2, 4), "s")
```

## 9) Comment inverser un dictionnaire (valeur -> clé) sans bug ?

```python
"""
Objectif
Inverser un dictionnaire proprement.

Piège
Si deux clés ont la même valeur, la dernière écrase la précédente.

Démarche
1) Inversion directe
2) Version robuste : regrouper les clés par valeur
"""

roles = {"u1": "admin", "u2": "user", "u3": "user"}

inverse_simple = {v: k for k, v in roles.items()}
print("Inverse simple :", inverse_simple)

inverse_robuste = {}
for user, role in roles.items():
```

## 17) Comment créer un pipeline lisible avec générateurs (filtrer puis transformer) ?

Créer le fichier **q17_pipeline_generateurs.py** :

```python
"""
Objectif
Créer un pipeline paresseux :
1) Filtrer
2) Transformer
3) Consommer

Intérêt
Très utile sur gros flux.
"""

def filtrer_vip(montants):
    for m in montants:
        if m > 100:
            yield m

def appliquer_remise(montants):
    for m in montants:
        yield round(m * 0.9, 2)

ventes = [50, 120, 300, 80, 150, 40]

pipeline = appliquer_remise(filtrer_vip(ventes))

print("Résultats :")
for x in pipeline:
    print(x)
```

## 18) Pourquoi un générateur peut “cacher” une exception jusqu’à la consommation ?

Créer le fichier **q18_exception_tardive.py** :

```python
"""
Objectif
Montrer qu’un générateur exécute le code au moment où on itère, pas avant.

Conséquence
Une erreur peut apparaître plus tard, au moment de next/for.
"""

def gen():
    yield 1
    yield 2
    # Erreur volontaire : division par zéro
    yield 10 / 0
    yield 3

g = gen()

print(next(g))
print(next(g))

try:
    print(next(g))
except ZeroDivisionError as e:
    print("Erreur détectée à la consommation :", e)
```
