# 1️⃣ Pourquoi les méthodes magiques ?

Les méthodes magiques (dunder methods) permettent :

- D’intégrer une classe au modèle interne du langage Python

- De redéfinir le comportement natif des opérateurs

- De rendre un objet compatible avec print, len, for, with, +, ==, etc.

- De contrôler la création et la gestion des attributs

Elles constituent le **Data Model Python**.

Sans elles, une classe reste passive.  
Avec elles, elle devient un citoyen natif du langage.

---

# 3️⃣ Cycle de vie d’un objet : **new** vs **init**

## Concept

- **new** → crée l’objet (allocation mémoire)

- **init** → initialise l’objet

---

## Exemple clair et commenté

Créer le fichier cycle_objet.py :

```python
"""
Explication
- __new__ est appelé en premier.
- Il doit retourner une instance valide.
- __init__ configure l'objet déjà créé.
"""

class Demo:

    def __new__(cls, *args, **kwargs):
        print("Phase __new__ : création mémoire")
        instance = super().__new__(cls)
        return instance

    def __init__(self):
        print("Phase __init__ : initialisation")

d = Demo()
```

Sortie attendue :

Phase **new** : création mémoire  
Phase **init** : initialisation

# 4️⃣ **str** vs **repr**

## Concept

- **str** → affichage utilisateur

- **repr** → représentation développeur

---

Créer le fichier affichage.py :

```python
"""
Explication
- print(obj) appelle __str__
- repr(obj) appelle __repr__
- Si __str__ absent → __repr__ est utilisé
"""

class Produit:

    def __init__(self, nom, prix):
        self.nom = nom
        self.prix = prix

    def __str__(self):
        return f"{self.nom} coûte {self.prix} TND"

    def __repr__(self):
        return f"Produit(nom={self.nom!r}, prix={self.prix!r})"

p = Produit("Clavier", 120)

print(p)
print(repr(p))
```

# 7️⃣ Transformer une classe en conteneur

Méthodes nécessaires :

**getitem**  
**len**  
**iter**

---

Créer le fichier conteneur.py :

```python
"""
Explication
- __getitem__ permet obj[index]
- __len__ permet len(obj)
- __iter__ permet for x in obj
"""

class ListePersonnalisee:

    def __init__(self):
        self._data = []

    def ajouter(self, valeur):
        self._data.append(valeur)

    def __getitem__(self, index):
        return self._data[index]

    def __len__(self):
        return len(self._data)

    def __iter__(self):
        return iter(self._data)

liste = ListePersonnalisee()
liste.ajouter("A")
liste.ajouter("B")

print("Premier élément :", liste[0])
print("Longueur :", len(liste))

for element in liste:
    print("Itération :", element)
```

# 1) Pourquoi **eq** doit retourner NotImplemented ?

## Énoncé

Que se passe-t-il si on compare avec un type différent ?

## Solution

```python
"""
Explication
- Si le type est incompatible, retourner NotImplemented
- Permet à Python d’essayer l'opération inverse
"""

    def __eq__(self, other):
        if not isinstance(other, A):
            return NotImplemented
        return True
```

# 3) Pourquoi **lt** seul ne suffit pas pour toutes les comparaisons ?

## Énoncé

Si on implémente seulement **lt**, pourquoi <= ou > peuvent échouer ?

## Solution

Créer le fichier q3_total_ordering.py :

```python
"""
Explication
- Implémenter seulement __lt__ et __eq__ ne fournit pas automatiquement
  toutes les autres comparaisons.
- functools.total_ordering génère les méthodes manquantes.
"""

from functools import total_ordering

@total_ordering
class Produit:

    def __init__(self, prix):
        self.prix = prix

    def __eq__(self, other):
        return self.prix == other.prix

    def __lt__(self, other):
        return self.prix < other.prix

p1 = Produit(10)
p2 = Produit(20)

print("p1 <= p2 :", p1 <= p2)
print("p1 > p2 :", p1 > p2)
```

# 20) Pourquoi le MRO est crucial avec les méthodes magiques ?

```python
"""
Explication
- En héritage multiple, l'ordre MRO détermine quelle méthode magique est appelée.
"""

class A:
    def __str__(self):
        return "A"

class B:
    def __str__(self):
        return "B"

class C(A, B):
    pass

c = C()

print("Affichage :", c)
print("MRO :", [cls.__name__ for cls in C.mro()])
```
