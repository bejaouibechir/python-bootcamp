```python
class Personne:
    def __init__(self,nom):
        self.__nom=nom

    @property
    def nom(self):
        print('De l\'extra code lancé avant le retour de __nom')
        return self.__nom
```

### 3. Les descripteurs

Il existe plusieurs modèles de conception couramment utilisés pour définir l'interface d'un objet.

a. **Getters** et **Setters** : Nous pouvons encapsuler chaque variable d'instance avec des fonctions qui obtiennent ou définissent la valeur de cette variable d'instance

b. **Propriétés** : Nous pouvons lier les fonctions getter , setter et deleter avec un nom d'attribut, en utilisant la fonction de propriété intégrée ou le décorateur @property

c. **Descripteurs** : Nous pouvons definir les fonctions getter, setter et deleter dans une classe séparée. Nous assignons ensuite un objet de cette classe au nom de l'attribut visé

**Note** : Les descripteurs sont liées au membres de classes

```python
class Personne:
    def __init__(self,nom=''):
        self.__nom = nom
    # getter
    def get_nom(self):
        #Pour vérifier que le nom commancer par une Majuscule
        return self.nom 

    # setter
    def set_nom(self,v):
        #Extra code personalisé
        self.nom = v
```

# 1️⃣ Pourquoi un décorateur casse parfois **name** et **doc** ?

## Énoncé

Pourquoi une fonction décorée perd son nom et sa documentation ?

## Explication

Quand on retourne wrapper, on remplace la fonction originale.  
Sans précaution, les métadonnées sont perdues.

Solution : utiliser functools.wraps.

---

```python
"""
Démonstration du problème :
- Sans wraps, le nom devient 'wrapper'
"""

def decor(fn):
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper


@decor
def mafonction():
    """Documentation originale"""
    print("Execution")

print("Nom:", mafonction.__name__)
print("Doc:", mafonction.__doc__)
```

Sortie observée :

Nom: wrapper  
Doc: None

---

Correction :

```python
"""
Solution correcte avec functools.wraps
"""

from functools import wraps

def decor(fn):
    @wraps(fn)
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper


@decor
def mafonction():
    """Documentation originale"""
    print("Execution")

print("Nom:", mafonction.__name__)
print("Doc:", mafonction.__doc__)
```

# 2️⃣ Pourquoi un décorateur mal écrit casse les arguments ?

## Énoncé

Pourquoi wrapper() sans *args, **kwargs est dangereux ?

---

```python
"""
Erreur classique :
Le wrapper ne transmet pas les arguments.
"""

def decor(fn):
    def wrapper():
        return fn()  # pas d'arguments transmis
    return wrapper


@decor
def addition(a, b):
    return a + b

try:
    print(addition(3, 4))
except TypeError as e:
    print("Erreur:", e)
```

Correction :

```python
def decor(fn):
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper
```

# 6️⃣ Pourquoi un Data Descriptor a priorité sur **dict** ?

---

```python
"""
Data Descriptor = définit __set__
Il prend priorité sur instance.__dict__
"""

class D:
    def __get__(self, instance, owner):
        return "Descriptor"

    def __set__(self, instance, value):
        instance.__dict__["x"] = value


class A:
    x = D()

a = A()
a.__dict__["x"] = "Direct"

print(a.x)  # priorité descriptor
```
