# 🧵 Threading & Coroutines en Python



# 1️⃣ Pourquoi la concurrence ?

Dans un système réel (e-commerce, API, serveur RH, système bancaire) :

- Plusieurs requêtes arrivent simultanément

- Certaines opérations sont lentes (I/O : base, réseau, fichiers)

- Certaines opérations sont intensives CPU

- Les données partagées doivent rester cohérentes

Objectifs :

- Réduire le temps global de traitement

- Éviter les incohérences

- Comprendre quand utiliser thread, processus ou coroutine

---

# 2️⃣ Threads vs Processus

## Définitions

- **Thread** → Exécution parallèle dans le même espace mémoire

- **Processus** → Exécution isolée avec mémoire indépendante

### Points clés

- Les threads partagent la mémoire

- Les processus ne partagent pas la mémoire

- Les threads nécessitent gestion de synchronisation

- Les processus sont plus coûteux à créer

---

# 3️⃣ Exécution séquentielle (Mono tâche)

## Exemple de traitement lent

```python
import time
from random import randint

class Traitement:

    def __init__(self, valeur):
        self.valeur = valeur  # Liste partagée

    def process(self):
        # Simulation d'une opération I/O lente
        time.sleep(randint(1, 3))

        if self.valeur[0] < 4:
            self.valeur[0] += 1
            print(f"Valeur actuelle: {self.valeur[0]}")
```

```python
valeur = [1]
t = Traitement(valeur)

debut = time.perf_counter()

for _ in range(3):
    t.process()

fin = time.perf_counter()

print("Temps total:", round(fin - debut, 2), "secondes")
```

Résultat : exécution strictement séquentielle.

# 4️⃣ Introduction au Threading

## Version multi-thread

```python
import time
from random import randint
from threading import Thread

class Traitement(Thread):

    def __init__(self, valeur):
        super().__init__()
        self.valeur = valeur  # Ressource partagée

    def run(self):
        time.sleep(randint(1, 3))

        if self.valeur[0] < 4:
            self.valeur[0] += 1
            print(f"Valeur actuelle: {self.valeur[0]}")
```

```python
valeur = [1]

debut = time.perf_counter()

threads = [Traitement(valeur) for _ in range(3)]

for t in threads:
    t.start()

for t in threads:
    t.join()

fin = time.perf_counter()

print("Temps total:", round(fin - debut, 2), "secondes")
```

Observation :

- Exécution plus rapide

- Risque de race condition

# 6️⃣ Lock (Mutex)

## Correction avec verrou

```python
from threading import Thread, Lock

class Compteur(Thread):

    def __init__(self, compteur, lock):
        super().__init__()
        self.compteur = compteur
        self.lock = lock

    def run(self):
        for _ in range(100000):
            with self.lock:  # Section critique protégée
                self.compteur[0] += 1
```

```python
compteur = [0]
lock = Lock()

t1 = Compteur(compteur, lock)
t2 = Compteur(compteur, lock)

t1.start()
t2.start()

t1.join()
t2.join()

print("Résultat sécurisé:", compteur[0])
```

Plus simple et sécurisée.

# 1) Pourquoi un thread peut accélérer une tâche I/O mais pas une tâche CPU ?

## Énoncé

Expliquer la différence entre une tâche I/O et une tâche CPU, et montrer pourquoi les threads aident surtout pour I/O.

## Solution

```python
"""
Explication
- Une tâche I/O attend (réseau, disque, base) : pendant l’attente, le CPU peut exécuter autre chose.
- Une tâche CPU calcule en continu : en CPython, le GIL limite l’exécution simultanée de code Python.
- Démo : I/O simulée avec sleep (threads efficaces), CPU simulé par calcul (threads peu efficaces).
"""

import time
from threading import Thread

def io_task(n: int):
    # Simule une attente I/O
    time.sleep(1)
    print(f"I/O {n} terminé")

def cpu_task(n: int):
    # Simule un calcul CPU
    total = 0
    for i in range(3_000_00):
        total += i
    print(f"CPU {n} terminé, total={total}")

def demo_io():
    debut = time.perf_counter()
    threads = [Thread(target=io_task, args=(i,)) for i in range(3)]
    for t in threads:
        t.start()
    for t in threads:
        t.join()
    fin = time.perf_counter()
    print("Temps I/O threads:", round(fin - debut, 2), "s")

def demo_cpu():
    debut = time.perf_counter()
    threads = [Thread(target=cpu_task, args=(i,)) for i in range(3)]
    for t in threads:
        t.start()
    for t in threads:
        t.join()
    fin = time.perf_counter()
    print("Temps CPU threads:", round(fin - debut, 2), "s")

demo_io()
demo_cpu()
```

## Énoncé

Montrer une incrémentation concurrente qui donne un résultat instable.

## Solution

```python

Explication
- Une opération compteur += 1 n’est pas atomique : lecture, calcul, écriture.
```

# 4) Lock : comment garantir la cohérence d’une section critique ?

## Énoncé

Corriger la question précédente avec un verrou.

## Solution

```python
"""
Explication
- Un verrou protège la section critique : un seul thread à la fois.
- with lock est préférable : acquisition et libération garanties.
"""

from threading import Thread, Lock

def incrementer(compteur: list[int], n: int, lock: Lock):
    for _ in range(n):
        with lock:
            compteur[0] += 1

compteur = [0]
lock = Lock()

t1 = Thread(target=incrementer, args=(compteur, 200_000, lock))
t2 = Thread(target=incrementer, args=(compteur, 200_000, lock))

t1.start()
t2.start()
t1.join()
t2.join()

print("Résultat:", compteur[0], "attendu:", 400_000)
```

# 5) Deadlock : comment le provoquer facilement ?

## Énoncé

Créer un deadlock avec deux verrous acquis dans des ordres opposés.

## Solution

```python
"""
Explication
- Un deadlock survient quand :
  1) T1 détient lockA et attend lockB
  2) T2 détient lockB et attend lockA
- Démo : deux threads bloqués.
- Astuce : exécuter puis interrompre manuellement si blocage.
"""

import time
from threading import Thread, Lock

lock_a = Lock()
lock_b = Lock()

def tache_1():
    with lock_a:
        print("T1 a lockA")
        time.sleep(0.2)
        print("T1 attend lockB")
        with lock_b:
            print("T1 a lockB")

def tache_2():
    with lock_b:
        print("T2 a lockB")
        time.sleep(0.2)
        print("T2 attend lockA")
        with lock_a:
            print("T2 a lockA")

t1 = Thread(target=tache_1)
t2 = Thread(target=tache_2)

t1.start()
t2.start()
t1.join(timeout=1)
t2.join(timeout=1)

print("Si les threads ne terminent pas, deadlock probable.")
```

# 6) Comment éviter un deadlock proprement ?

## Énoncé

Montrer une stratégie simple et robuste.

## Solution

```python
"""
Explication
- Stratégie : imposer un ordre global d’acquisition (toujours lockA puis lockB).
- Même si plusieurs threads, l’ordre unique supprime le cycle d’attente.
"""

import time
from threading import Thread, Lock

lock_a = Lock()
lock_b = Lock()

def worker(n: int):
    with lock_a:
        time.sleep(0.1)
        with lock_b:
            print("Worker", n, "a acquis lockA puis lockB")

threads = [Thread(target=worker, args=(i,)) for i in range(3)]
for t in threads:
    t.start()
for t in threads:
    t.join()

print("Terminé sans deadlock.")
```

# 7) Semaphore : pourquoi ce n’est pas un Lock ?

## Énoncé

Montrer la différence entre accès exclusif et limitation de concurrence.

## Solution

```python
"""
Explication
- Lock : 1 seul thread à la fois (exclusif).
- Semaphore(k) : jusqu’à k threads simultanément.
- Démo : 2 threads peuvent entrer en même temps, le 3e attend.

import time

sem = Semaphore(2)

        print("Requête", n, "entre")
        time.sleep(1)
        print("Requête", n, "sort")

threads = [Thread(target=requete, args=(i,)) for i in range(1, 5)]
for t in threads:
    t.start()
for t in threads:
    t.join()
```

# 8) RLock : à quoi ça sert concrètement ?

## Énoncé

Montrer un cas où un Lock simple casse le programme, mais RLock fonctionne.

## Solution

```python
"""
Explication
- Un Lock simple ne peut pas être repris par le même thread : blocage.
- Un RLock permet au même thread de ré-acquérir le verrou plusieurs fois.
- Démo : fonction qui appelle une autre fonction verrouillée.
"""

from threading import RLock

lock = RLock()
solde = [100]

def crediter(montant: int):
    with lock:
        solde[0] += montant

def transferer(montant: int):
    with lock:
        # Appel interne qui reprend le même verrou
        crediter(montant)
        print("Solde après transfert:", solde[0])

transferer(50)
```

# 9) Condition : pourquoi wait doit être dans une boucle ?

## Énoncé

Montrer qu’un réveil peut arriver sans que la condition logique soit vraie.

## Solution

```python
"""
Explication
- Une Condition coordonne des threads, mais un réveil ne garantit pas l’état attendu.
- Bonne pratique : attendre dans une boucle while sur une condition métier.
- Démo : producteur/consommateur sécurisé.
"""

import time
from threading import Thread, Condition

condition = Condition()
buffer: list[int] = []

def producteur():
    for x in [10, 20, 30]:
        time.sleep(0.2)
        with condition:
            buffer.append(x)
            print("Produit:", x)
            condition.notify()

def consommateur():
    for _ in range(3):
        with condition:
            while not buffer:
                condition.wait()
            x = buffer.pop(0)
            print("Consommé:", x)

t1 = Thread(target=producteur)
t2 = Thread(target=consommateur)
t1.start()
t2.start()
t1.join()
t2.join()
```

# 10) Queue : pourquoi c’est souvent meilleur que Lock + liste ?

## Énoncé

Montrer un producteur/consommateur simple, sans verrou explicite.

## Solution

```python
"""
Explication
- Queue est thread-safe : pas besoin de Lock manuel.
- get bloque jusqu’à disponibilité, task_done signale la fin du traitement.
- Démo : pipeline simple.
"""

import time
from threading import Thread
from queue import Queue

        q.put(x)
        print("Produit:", x)

def consommateur():
    for _ in range(3):
        x = q.get()
        print("Consommé:", x)
        q.task_done()

t1 = Thread(target=producteur)
t2 = Thread(target=consommateur)
t1.start()
t2.start()

q.join()
t1.join()
t2.join()

print("Pipeline terminé.")
```

# 15) Predict : que renvoie gather si une coroutine échoue ?

## Énoncé

Montrer le comportement par défaut et la variante qui récupère les exceptions.

## Solution

```python
"""
Explication
- Par défaut, gather propage la première exception.
- Avec return_exceptions=True, on récupère résultats + exceptions.
"""

import asyncio

async def ok():
    await asyncio.sleep(0.1)
    return "OK"

async def ko():
    await asyncio.sleep(0.05)
    raise ValueError("Erreur métier")

async def main():
    try:
        res = await asyncio.gather(ok(), ko())
        print("Résultats:", res)
    except Exception as e:
        print("Exception propagée:", type(e).__name__, str(e))

    res = await asyncio.gather(ok(), ko(), return_exceptions=True)
    print("Mode return_exceptions:", res)

asyncio.run(main())
```

# 17) asyncio Semaphore : comment limiter la concurrence proprement ?

Simuler 10 appels I/O mais en limiter 3 simultanément.

## Solution

```python
"""
Explication
- Limiter la concurrence évite de saturer API, DB, réseau.
- asyncio.Semaphore contrôle le nombre de tâches simultanées.
"""

import asyncio

sem = asyncio.Semaphore(3)

async def appel(n: int):
    async with sem:
        print("Start", n)
        await asyncio.sleep(0.2)
        print("End", n)
        return n

async def main():
    tasks = [appel(i) for i in range(1, 11)]
    res = await asyncio.gather(*tasks)
    print("Total résultats:", len(res))

asyncio.run(main())
```

```python
    return "Résultat bloquant"

async def main():
    loop = asyncio.get_running_loop()
    print("Avant exécuteur")
    res = await loop.run_in_executor(None, bloquant)
    print("Après exécuteur:", res)

asyncio.run(main())
```

# 19) Timeout : comment protéger un appel async qui peut se bloquer ?

## Énoncé

Montrer un timeout clair et observable.

## Solution

```python
"""
Explication
- wait_for impose une limite : si dépassée, TimeoutError.
- Utile pour appels réseau instables.
"""

import asyncio

async def lent():
    await asyncio.sleep(1)
    return "OK"

async def main():
    try:
        res = await asyncio.wait_for(lent(), timeout=0.2)
        print(res)
    except asyncio.TimeoutError:
        print("Timeout déclenché")

asyncio.run(main())
```

# 20) Mini défi : pipeline e-commerce (ingestion, traitement, sortie)

## Énoncé

Construire un mini pipeline : un producteur crée des commandes, un consommateur traite, puis confirme.

## Solution

```python
"""
Explication
- Modèle très courant : ingestion → file → workers → ack.
- Ici : Queue thread-safe + deux workers.
- Démo : affichage du flux complet.
"""

import time
from threading import Thread
from queue import Queue

q: Queue[dict] = Queue()

def producteur():
    commandes = [
        {"id": 101, "montant": 50},
        {"id": 102, "montant": 120},
        {"id": 103, "montant": 30},
        {"id": 104, "montant": 90},
    ]
    for c in commandes:
        time.sleep(0.1)
        q.put(c)
        print("Reçu commande:", c["id"])
    print("Producteur terminé")

def worker(n: int):
    while True:
        commande = q.get()
        if commande is None:
            q.task_done()
            print("Worker", n, "stop")
            return

        # Traitement métier simulé
        time.sleep(0.2)
        decision = "ACCEPTÉE" if commande["montant"] <= 100 else "REVUE"
        print("Worker", n, "traite", commande["id"], "=>", decision)

        q.task_done()

t_prod = Thread(target=producteur)
t_w1 = Thread(target=worker, args=(1,))
t_w2 = Thread(target=worker, args=(2,))

t_prod.start()
t_w1.start()
t_w2.start()

t_prod.join()
q.join()

# Stop des workers via sentinelles
q.put(None)
q.put(None)
q.join()

t_w1.join()
t_w2.join()

print("Pipeline complet.")
```
