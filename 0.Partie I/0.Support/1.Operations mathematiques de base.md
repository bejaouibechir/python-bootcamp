# 1. Nature des nombres en Python

- **Trois types numériques** : `int` (entiers), `float` (décimaux), `complex` (hors scope)  
- `type()` permet de **vérifier le type** d'une valeur

Python manipule principalement trois types numériques :

- int → nombres entiers
- float → nombres décimaux (représentation binaire IEEE 754)
- complex → nombres complexes (hors périmètre ici)

Vérification rapide :

```python
print(type(10))      # int
print(type(10.5))    # float
```

---

# 2. Addition

- **Opérateur `+`** : additionne deux nombres  
- **Règle de propagation** : si un `float` est impliqué → résultat `float`

L’opérateur + additionne deux valeurs numériques.

```python
print(2 + 3)
print(2 + 3.0)
```

Sortie attendue :

```
5
5.0
```

### Point important

Si un float est impliqué → le résultat devient float.

---

# 3. Soustraction

- **Opérateur `-`** : soustrait deux nombres  
- **Même règle** : présence d’un `float` → résultat `float`

```python
print(10 - 4)
print(10.5 - 4)
```

Sortie :

```
6
6.5
```

---

# 4. Multiplication

- **Opérateur `*`** : multiplie deux nombres  
- **Résultat `float`** si l’un des opérandes est `float`

```python
print(4 * 5)
print(4 * 2.5)
```

Sortie :

```
20
10.0
```

# 5. Division réelle (/)

- **Toujours un `float`**, même pour une division exacte  
- **Piège** : `4 / 2` donne `2.0`, pas `2`

```python
print(10 / 2)
print(10 / 4)
```

Sortie :

```
5.0
2.5
```

### Piège fréquent

```python
print(4 / 2)
```

Sortie :

```
2.0   # pas 2
```

# 6. Division entière (//)

- **Renvoie la partie entière** du quotient (floor)  
- **Attention aux négatifs** : `-10 // 3` donne `-4` (floor, pas troncature vers zéro)

Renvoie la partie entière après division.

```python
print(10 // 3)
print(10 // 2)
```

Sortie :

```
3
5
```

### Cas négatif (important)

```python
print(-10 // 3)
```

Sortie :

```
-4
```

Explication :  
La division entière tronque vers le bas (floor), pas vers zéro.

# 7. Modulo (%)

- **Reste de la division** euclidienne  
- **Relation clé** : `a = (a // b) * b + (a % b)` toujours vraie

Renvoie le reste de la division.

```python
print(10 % 3)
```

Sortie :

```
1
```

Relation mathématique :

a == (a // b) * b + (a % b)

Vérification :

```python
a = 10
b = 3

print(a == (a // b) * b + (a % b))
```

# 8. Puissance (**)

- **Exposant** : `a ** b` = a puissance b  
- **Exposant fractionnaire** → racine (ex: `9 ** 0.5` = `3.0`)

```python
print(2 ** 3)
print(9 ** 0.5)
```

Sortie :

```

3.0
```

# 9. Priorité des opérations

- **Ordre** : Parenthèses > Puissance > `* / // %` > `+ -`  
- **Utiliser des parenthèses** pour lever toute ambiguïté

Ordre :

1. Parenthèses
2. Puissance
3. Multiplication / Division / Division entière / Modulo
4. Addition / Soustraction

# 13. Précision des float (concept fondamental)

- **Représentation binaire** → certains décimaux (ex: `0.1`) sont approximatifs  
- **Conséquence** : `0.1 + 0.2 ≠ 0.3` exactement  
- **Solution métier** : utiliser `Decimal` pour la finance

```python
print(0.1 + 0.2)
```

Sortie :

```
0.30000000000000004
```

Explication :  
Représentation binaire approximative des nombres décimaux.

Solution métier (finance, facturation) :

```python
from decimal import Decimal

a = Decimal("0.1")
b = Decimal("0.2")

print(a + b)
```

Sortie :

```
0.3
```

## 1) Pourquoi 0.1 + 0.2 ne donne pas exactement 0.3 ?

- **Problème de représentation binaire** des flottants  
- `0.1` et `0.2` sont **approximatifs** en binaire → accumulation d’erreur  
- **Comparaison directe** avec `==` échoue  
- **Solution** : `math.isclose()` ou `Decimal`

### Énoncé

Expliquer le comportement inattendu des nombres flottants en Python.

### Solution

```python
"""
Explication
Les nombres float sont représentés en binaire (IEEE 754).
Certaines valeurs décimales comme 0.1 et 0.2 ne peuvent pas être représentées exactement.
Le résultat affiché montre donc l’approximation binaire interne.
"""

print("Addition float classique :")
resultat = 0.1 + 0.2
print(resultat)

print("\nComparaison avec 0.3 :")
print(resultat == 0.3)

print("\nSolution adaptée pour calculs précis (finance) :")
from decimal import Decimal

a = Decimal("0.1")
b = Decimal("0.2")
print(a + b)
```

## 2) Pourquoi 4 / 2 retourne 2.0 et non 2 ?

```python

Explication
L’opérateur / effectue une division réelle.
Python 3 a unifié le comportement pour toujours retourner un float.
Si on veut un entier, il faut utiliser // ou convertir explicitement.
"""

print(4 / 2)
```

## 4) Pourquoi -5 // 2 retourne -3 ?

### Solution

```python

Explication

"""

```

## 5) Relation fondamentale entre // et %

- Python la **garantit** pour tous les entiers

### Énoncé

Démontrer la relation mathématique a = (a // b) * b + (a % b)

### Solution

```python
"""
Explication
```

## 7) Pourquoi round(2.5) donne 2 ?

- **Banker’s rounding** (arrondi au pair) :  
  - Les **.5** sont arrondis vers l’entier pair le plus proche  
  - `2.5` → 2 (pair), `3.5` → 4 (pair)

### Énoncé

Expliquer le rounding bancaire.

### Solution

```python
"""
Explication
Python utilise l'arrondi au pair (Banker's rounding).
2.5 devient 2 car 2 est pair.
3.5 devient 4.
"""

print(round(2.5))
print(round(3.5))
```

## 20) Cas métier : calcul de remise

- **Précision financière** → utiliser `Decimal` (pas `float`)  
- Éviter les erreurs d’arrondi sur les montants

### Énoncé

Calculer un total avec remise et TVA en évitant les erreurs float.

### Solution

```python
"""
Explication
Pour des calculs financiers, utiliser Decimal.
Éviter float pour garantir la précision.
"""

from decimal import Decimal

prix = Decimal("199.99")
remise = Decimal("0.10")
tva = Decimal("0.19")

total = prix * (1 - remise)
total_ttc = total * (1 + tva)

print("Total après remise :", total)
print("Total TTC :", total_ttc)
```
