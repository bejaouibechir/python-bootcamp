# 1️⃣ Pourquoi gérer les erreurs ?

Dans tout programme réel :

- Division par zéro

- Fichier introuvable

- Donnée utilisateur invalide

- Connexion réseau interrompue

- Clé inexistante dans un dictionnaire

Sans gestion d'erreur, le programme s'arrête brutalement.

Objectif :

- Rendre le code robuste

- Contrôler le flux d'exécution

- Fournir des messages explicites

- Garantir une terminaison propre

# 2️⃣ Comprendre une exception

Une exception est un objet représentant une anomalie détectée à l'exécution.

```python
"""
Sans gestion, une exception arrête immédiatement le programme.
"""

def division(a, b):
    return a / b

print(division(10, 0))    # ZeroDivisionError → arrêt brutal
```

# 3️⃣ Bloc try / except

```python
"""
try    : contient le code risqué
except : traite l'exception si elle survient
Toujours capturer le type d'exception le plus précis possible.
"""

def division(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        print("Division par zéro interdite")
        return None

print(division(10, 0))
print(division(10, 2))
```

---

# 4️⃣ Capturer l'objet exception

```python
"""
Le mot clé as permet d'accéder à l'objet exception.
Il contient le message d'erreur et les attributs de l'exception.
"""

def division(a, b):
    try:
        return a / b
    except ZeroDivisionError as erreur:
        print("Erreur détectée :", erreur)
        return None

division(10, 0)
```

# 7️⃣ except Exception — usage contrôlé

```python
"""
Exception est la classe de base des exceptions courantes.
Elle n'inclut pas KeyboardInterrupt ni SystemExit.
Ne jamais utiliser except: nu — il capture TOUT.
"""

# Dangereux
try:
    x = 1 / 0
except:                     # ❌ capture KeyboardInterrupt et SystemExit
    print("Erreur capturée")

# Correct
try:
    x = 1 / 0
except Exception as e:      # ✅ exclut les interruptions système
    print("Erreur :", e)
```

# 9️⃣ La clause finally

```python
"""
finally s'exécute TOUJOURS — qu'il y ait exception ou non.
Indispensable pour libérer les ressources.
"""

def ouvrir_fichier(nom):
    fichier = None
    try:
        fichier = open(nom, "r")
        print(fichier.read())
    except FileNotFoundError:
        print("Fichier introuvable")
    finally:
        if fichier:
            fichier.close()
        print("Bloc finally exécuté")

ouvrir_fichier("test.txt")
```

### finally et return

```python
"""
finally s'exécute même si try contient un return.
Un return dans finally écrase celui du try.
"""

def test():
    try:
        return "Try"
    finally:
        print("Finally exécuté")    # toujours affiché

print(test())    # "Try" — mais finally s'exécute avant
```

# 🔟 Gestionnaire de contexte — with

```python
"""
with garantit la libération des ressources même en cas d'exception.
Équivalent propre du try/finally pour les ressources.
Plus lisible et plus sûr que la gestion manuelle.
"""

# Sans with — risqué
fichier = None
try:
    fichier = open("data.txt", "r")
    contenu = fichier.read()
finally:
    if fichier:
        fichier.close()

# Avec with — recommandé
try:
    with open("data.txt", "r") as f:
        contenu = f.read()
        print(contenu)
except FileNotFoundError:
    print("Fichier absent")
```

# 1️⃣4️⃣ Exception personnalisée

```python
"""
Créer ses propres exceptions pour les cas métier.
Hériter de Exception.
Enrichir avec des attributs métier.
"""

class SoldeInsuffisantError(Exception):
    def __init__(self, solde: float, montant: float):
        self.solde   = solde
        self.montant = montant
        super().__init__(f"Solde {solde} € insuffisant pour retirer {montant} €")

def retirer(solde: float, montant: float) -> float:
    if montant > solde:
        raise SoldeInsuffisantError(solde, montant)
    return solde - montant

try:
    retirer(100, 200)
except SoldeInsuffisantError as e:
    print(e)
    print(f"Manque : {e.montant - e.solde} €")
```

# 1️⃣5️⃣ Hiérarchie des exceptions

```python
"""
BaseException
└── Exception
    ├── ValueError
    ├── TypeError
    ├── ZeroDivisionError
    ├── IndexError
    ├── KeyError
    ├── FileNotFoundError
    └── AttributeError

Capturer un parent capture aussi ses enfants.
"""

# Démonstration parent / enfant
try:
    1 / 0
except ArithmeticError:             # parent de ZeroDivisionError
    print("ArithmeticError capturé")

# Vérification via isinstance
try:
    1 / 0
except Exception as e:
    print(isinstance(e, ZeroDivisionError))    # True
    print(isinstance(e, ArithmeticError))      # True
    print(isinstance(e, Exception))            # True
```

## Saisie robuste

```python
"""
Boucle de saisie avec retry contrôlé.
"""

def saisir_entier(max_tentatives: int = 3) -> int:
    tentatives = 0
    while tentatives < max_tentatives:
        try:
            return int(input("Entrez un entier : "))
        except ValueError:
            tentatives += 1
            restantes = max_tentatives - tentatives
            print(f"Valeur incorrecte. Tentatives restantes : {restantes}")
    raise RuntimeError("Nombre maximum de tentatives atteint")

try:
    x = saisir_entier()
    print("Valeur valide :", x)
except RuntimeError as e:
    print("Abandon :", e)
```

```python
"""
Conversion robuste avec gestion d'exceptions chaînées.
"""

class ConversionError(ValueError):
    def __init__(self, valeur: str):
        self.valeur = valeur
        super().__init__(f"Impossible de convertir '{valeur}' en nombre")

def convertir_nombre(chaine: str):
    """
    Convertit une chaîne en nombre.

    Args:
        chaine : Chaîne à convertir.

    Returns:
        Tuple (valeur convertie, type).

    Raises:
        ConversionError : Si la conversion est impossible.
    """
    try:
        valeur = int(chaine)
        return valeur, int
    except ValueError:
        pass

    try:
        valeur = float(chaine)
        return valeur, float
    except ValueError:
        raise ConversionError(chaine)

for test in ["42", "3.14", "abc"]:
    try:
        valeur, type_val = convertir_nombre(test)
        print(f"'{test}' → {valeur} ({type_val.__name__})")
    except ConversionError as e:
        print(f"Erreur : {e}")
```

# Synthèse

- `try/except` capture et traite les exceptions

- `else` s'exécute uniquement si aucune exception n'est levée

- `finally` s'exécute toujours — même avec `return` ou exception non capturée

- `with` garantit la libération des ressources — préférer à `try/finally` manuel

- Toujours capturer le type d'exception le plus précis

- Ne jamais utiliser `except:` nu — utiliser au minimum `except Exception`

- `raise` sans argument relance en conservant la trace originale

- `raise ... from ...` chaîne les exceptions et préserve la cause racine

- Les exceptions personnalisées enrichissent les cas métier

- `contextlib.suppress` ignore proprement une exception attendue

- Logger les erreurs avec `logging` plutôt qu'afficher avec `print`

# 18) Logging d'erreur

## Énoncé

Pourquoi logger plutôt que print ?

## Solution

```python
"""
Explication :
logging permet de configurer niveau, format et destination.
exc_info=True ajoute la stack trace complète.
Indispensable en production.
"""

import logging

logging.basicConfig(
    level=logging.ERROR,
    format="%(asctime)s — %(levelname)s — %(message)s"
)

try:
    1 / 0
except ZeroDivisionError:
    logging.error("Division par zéro détectée", exc_info=True)
```

# 19) Retry contrôlé

## Énoncé

Comment implémenter un retry simple ?

## Solution

```python
"""
Explication :
Boucle avec compteur de tentatives.
Abandon après le nombre maximum atteint.
"""

MAX = 3

for tentative in range(1, MAX + 1):
    try:
        x = int(input(f"Tentative {tentative}/{MAX} — Nombre : "))
        print("Valide :", x)
        break
    except ValueError:
        print("Valeur incorrecte")
else:
    print("Abandon après", MAX, "tentatives")
```

# 20) Gestion propre d'un flux complet

## Énoncé

Construire un flux robuste combinant try, except, else, finally.

## Solution

```python
"""
Explication :
Combinaison complète de tous les blocs.
try     → code risqué
except  → traitement de l'erreur
else    → exécuté si aucune exception
finally → exécuté dans tous les cas
"""

class OperationError(Exception):
    pass

def operation(a: float, b: float) -> float:
    if b == 0:
        raise OperationError("Division interdite")
    return a / b

try:
    resultat = operation(10, 2)
except OperationError as e:
    print("Erreur :", e)
else:
    print("Succès :", resultat)
finally:
    print("Fin du traitement")
```
